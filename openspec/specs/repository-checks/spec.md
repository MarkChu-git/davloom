# repository-checks Specification

## Purpose
让贡献者在本地用一条命令确认代码质量和构建状态。后续的 CI 复用同一入口，本地和 CI 的检查因此保持一致。

## Requirements

### Requirement: 统一检查命令
仓库 SHALL 提供一条根目录命令，运行 lint、格式检查、类型检查、单元测试和全部应用的生产构建。任何一项失败时，该命令 MUST 以非零状态退出。

#### Scenario: 全部检查通过
- **WHEN** 贡献者在干净的检出目录安装依赖后运行统一检查命令
- **THEN** 命令运行全部检查项并以状态 0 退出

#### Scenario: 某一项检查失败
- **WHEN** 代码存在一个类型错误，贡献者运行统一检查命令
- **THEN** 命令以非零状态退出，并在输出中指出失败的检查项

### Requirement: 依赖版本可复现
仓库 MUST 提交依赖锁文件，并用精确版本固定设计系统及其样式编译依赖。

#### Scenario: 按锁文件安装
- **WHEN** 贡献者按冻结锁文件的方式安装依赖
- **THEN** 安装成功，锁文件没有变化

#### Scenario: 设计系统版本固定
- **WHEN** 脚本检查根目录和各工作区的依赖声明
- **THEN** 设计系统及其样式编译依赖都声明为精确版本，不含 `^` 或 `~`
