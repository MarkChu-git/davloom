**Davloom 1.0 is the first stable release: your own WebDAV drive, free on Cloudflare Workers or
self-hosted with Docker, with a web Dashboard to run it.**

Mount it in macOS Finder, Windows Explorer, rclone, davfs2 or any other WebDAV client. Manage
storage, Mounts, API Keys and your account from the browser, in English or Simplified Chinese, on a
phone or a wide screen.

## Highlights

### A complete WebDAV server

- **Class 1 and 2 of RFC 4918**: every method, with LOCK and UNLOCK, so clients mount it read-write.
  litmus, rclone, cadaver and davfs2 run against every build, Davloom passes every litmus suite,
  and macOS Finder was accepted against the live deployment.
- **Conditional requests and byte ranges** (RFC 9110): entity tags, `If-Match`, `If-None-Match`,
  `If-Range`, the WebDAV `If` header with lock tokens, and `Range` requests for resumed downloads
  and media seeking.
- **Dead properties** with PROPPATCH, and quota properties for each Mount.
- **Finder at the bare address**: `https://<host>` answers WebDAV with a redirect to `/dav/`, while a
  browser opening the same address gets the Dashboard.

### Storage you choose

- **Cloudflare Durable Objects**, the free default: files are kept in 1 MiB rows of a SQLite-backed
  Durable Object, so the whole drive runs on the Workers Free plan with no payment method.
- **Cloudflare R2** and **any S3-compatible store**, such as RustFS, MinIO or AWS S3.
- **Mounts** publish a backend, or a folder in one, at `/dav/<mount>/`, and files can be moved
  between Mounts and backends from the Dashboard.

### Access that stays small

- **API Keys for clients**: each key is Read Only or Read / Write, may expire, and may be limited to
  some Mounts or folders. The administrator's password never works over WebDAV.
- **Owner account**: the first account becomes the owner and registration then closes. Sign-in
  takes two-step verification and passkeys, and anything that destroys data asks again for your
  password, authenticator code or passkey.
- **Audit log** of what changed, and who changed it.

### Proven decisions

The rules that decide an outcome without I/O are written in Bend 2 and proven: namespace operations,
conditional requests, byte ranges, locks and the `If` header, permissions and key scopes, names
and path bounds, HTTP framing, PROPFIND and the failure-to-status map. `packages/laws/LAWS.bend`
states every guarantee, `PROOF.bend` proves each one, and the code that runs is compiled from the
code that was proven. No law in this release is unproven.

### The Dashboard

Files, Storage and Mounts, Credentials, Activity and Settings, built with Astryx: light and dark
mode, English and Simplified Chinese, and at or above 96 in every
Lighthouse category on every page, on desktop and mobile. Settings can be exported and imported to
move an instance.

## Get started

### Cloudflare Workers

Select **Deploy to Cloudflare** in the [README](https://github.com/MarkChu-git/davloom#readme), or
deploy by hand with Bun and Wrangler as
[docs/deployment/cloudflare.md](https://github.com/MarkChu-git/davloom/blob/v1.0.0/docs/deployment/cloudflare.md)
shows. Then open the Dashboard and create your account.

What the Free plan allows:

| Limit                                               | What it means for Davloom                                                  |
| --------------------------------------------------- | -------------------------------------------------------------------------- |
| 100 MB request body                                 | A single upload is at most 100 MB.                                         |
| 1 GB per Durable Object, 5 GB per account           | One Durable Objects backend holds about 1 GB; add backends for more.       |
| 100,000 Durable Object rows written per day         | About 100 GB of uploads a day at 1 MiB a row, fewer with many small files. |
| D1: 5 million rows read and 100,000 written per day | API Keys are cached for 30 s, so a WebDAV client costs few reads.          |

### Docker

The image below runs Davloom on Bun with SQLite and an S3-compatible store. To use it with the
Compose file in the repository, replace the `build:` section of the `davloom` service in
`deploy/docker/compose.yaml` with `image: ghcr.io/markchu-git/davloom:v1.0.0`, write
`deploy/docker/.env` as
[docs/deployment/docker.md](https://github.com/MarkChu-git/davloom/blob/v1.0.0/docs/deployment/docker.md)
shows, and run `docker compose -f deploy/docker/compose.yaml up -d`. The image is built for
`linux/amd64` and `linux/arm64`.

### Connect a client

Create an API Key on **Credentials**, then mount `https://<host>/dav/`: any username, and the key as
the password.

## How it was tested

- Unit tests with coverage gates for every package, and mutation testing with StrykerJS: the WebDAV
  engine scores above 96%, against a gate of 80%.
- Protocol, security, quota and concurrency suites against the production Worker in local workerd
  and against the self-hosted server in Docker, with litmus, rclone, cadaver and davfs2 as real
  clients.
- Hundreds of browser tests in Chromium, Firefox and WebKit, with screenshots of every page in light
  and dark mode, on desktop and phone.
- Lighthouse on every Dashboard page, and an acceptance pass with macOS Finder against the live
  deployment.
- Each image is scanned with Trivy for High and Critical vulnerabilities and misconfigurations, has
  its licenses checked, and ships with an SPDX SBOM and build provenance attested by GitHub.

## Good to know

- **Upgrades only go forward.** Back up before upgrading, and see
  [docs/deployment/release.md](https://github.com/MarkChu-git/davloom/blob/v1.0.0/docs/deployment/release.md)
  for rolling back on Docker and on Workers.
- **R2 needs a payment method** on your Cloudflare account; Davloom offers the R2 kind only when the
  Worker has an R2 binding.
- **Security**: [docs/security.md](https://github.com/MarkChu-git/davloom/blob/v1.0.0/docs/security.md)
  lists how each security requirement is met and which tests hold it.
