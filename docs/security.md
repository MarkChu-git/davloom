# Security

This page checks each security requirement of PRD §12 against the code and the tests that hold it.
Report a vulnerability privately to the repository owner rather than in a public issue.

| Requirement                                 | How Davloom meets it                                                                                                                                                                                                                                                                                                                                                                                            | Held by                                                                                                                                                                                                                                     |
| ------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Private buckets by default                  | The Durable Objects backend has no public address. Davloom creates S3 buckets with no ACL, which makes them private, and R2 buckets are private unless their owner publishes them. Davloom reads and writes buckets only with credentials it keeps.                                                                                                                                                             | `apps/api/src/instance.bun.ts` (`ensureDefaultBucket`)                                                                                                                                                                                      |
| WebDAV over HTTPS only                      | Workers serve HTTPS. Over plain HTTP, WebDAV and the API answer only requests from the machine itself, or behind a proxy that sends `X-Forwarded-Proto: https`, unless `DAVLOOM_ALLOW_HTTP=1` allows a trusted network. Anything else gets 403. A proxy that serves plain HTTP to other machines and forwards to `localhost` would defeat the check, so a proxy must serve HTTPS (`docs/deployment/docker.md`). | `apps/api/src/app.ts` (`isInsecure`); the HTTPS table in `apps/api/src/app.test.ts`                                                                                                                                                         |
| All file access is authorized               | Every WebDAV request needs an API Key over Basic Auth, or the Dashboard's session with its marker header. The policy decides from the key's access level and scope, for the target and for the destination of COPY and MOVE.                                                                                                                                                                                    | The laws `authorize_matches_spec`, `read_only_never_writes`, `denied_outside_scope` and the four `scope_*` laws; the permission table of 480 cases (`packages/webdav/src/tables/permissions.test.ts`), which compat runs on Workers and Bun |
| Secrets in platform secrets or encrypted    | `DAVLOOM_SECRET` and `DAVLOOM_SETUP_TOKEN` come from Workers secrets or the environment. S3 secret keys are stored sealed with AES-256-GCM under a key derived from `DAVLOOM_SECRET`, bound to their backend. Exports are encrypted under a random key shown once.                                                                                                                                              | `packages/core/src/credentials.ts`, `packages/core/src/archive.ts` and their tests                                                                                                                                                          |
| API Keys not kept in plaintext              | Better Auth stores only the key's SHA-256, and Davloom looks keys up by that hash. The key is shown once, when it is created.                                                                                                                                                                                                                                                                                   | `hashApiKey` in `packages/core/src/instance.ts`; `apikey.key` in `packages/database/src/schema.ts`                                                                                                                                          |
| Path traversal                              | Paths are decoded once, per segment. A name is refused when it is empty, `.` or `..`, holds `/`, NUL or a lone surrogate, or runs past 255 bytes, and a path past 900 bytes is refused. A Mount resolves only inside its root, and a scoped key reaches nothing outside its roots.                                                                                                                              | The laws `name_rejects_dots`, `name_rejects_separators`, `name_bounded`, `path_bounded`, `name_accepted` and `scope_outside_denied`; `packages/webdav/src/tables/traversal.test.ts`                                                         |
| XML body size and complexity                | Request bodies parse with saxes, which expands no entities but the five predefined ones and fetches nothing. A document type declaration is refused, and so is a body over 1 MiB, nested deeper than 64 or holding more than 20,000 elements.                                                                                                                                                                   | `packages/webdav/src/xml.ts`; `packages/webdav/src/tables/xml-bodies.test.ts`                                                                                                                                                               |
| Recursive operations                        | PROPFIND with `Depth: infinity` on a collection answers 403 `propfind-finite-depth`. A COPY or MOVE touches at most a fixed number of entries, and over that limit it changes nothing. Uploads stop at the largest file size, and XML bodies at the limits above.                                                                                                                                               | The law `limit_exact`; `packages/storage/src/move-recovery.test.ts`; `packages/webdav/src/tables/propfind.test.ts`                                                                                                                          |
| Conditional requests                        | GET, HEAD, PUT and the other methods evaluate `If-Match`, `If-None-Match`, `If-Modified-Since`, `If-Unmodified-Since` and `If-Range` in RFC 9110 order, and the `If` header with lock tokens and entity tags.                                                                                                                                                                                                   | The laws `preconditions_in_rfc_order` and the `range_*` laws; `entity-tags.test.ts`, `if-header.test.ts` and `range.test.ts` in `packages/webdav/src/tables`                                                                                |
| No sensitive authentication content in logs | Davloom logs errors without request headers, keys, cookies or secrets: credential errors carry no secret by construction, and the import logs only the database's message.                                                                                                                                                                                                                                      | `packages/core/src/credentials.ts` (`CredentialsError`); a review of every `console.*` call in `apps` and `packages`                                                                                                                        |
| Cross-Mount operations denied               | A COPY or MOVE between two backends is refused with 502. A scoped key's destination must lie inside its roots.                                                                                                                                                                                                                                                                                                  | The law `scope_destination_inside`; the `cross-backend` cases of the storage and permission tests                                                                                                                                           |
| Rules proven in Bend 2                      | Every decision above that takes no IO is compiled from Bend, and `packages/laws/LAWS.bend` states its laws. Both `bend PROOF.bend` and `bend PROOF.bend --verdict` print ALL PROOFS CHECK for all 44 laws, in CI on every pull request.                                                                                                                                                                         | `.github/workflows/laws.yml`; `bun run laws:check`                                                                                                                                                                                          |

## Supply chain and repository

- OSV-Scanner checks every package in `bun.lock` on each pull request and every week. Each exception in `osv-scanner.toml` gives its reason and an expiry date (`docs/ci.md`).
- Gitleaks scans each pull request's commits for secrets. CodeQL analyses the TypeScript, and actionlint and zizmor check the workflows.
- Dependencies are pinned to exact versions, and actions to full commit SHAs.
- No known Critical vulnerability is open: on the day of this check, the dependency scan reports none, and no exception covers one.
