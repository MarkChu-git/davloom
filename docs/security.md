# Security

This page checks each security requirement of PRD §12 against the code and the tests that hold it.
Report a vulnerability privately to the repository owner rather than in a public issue.

## Step-up verification

Every route of the API needs an entry in `API_ACTIONS` in `apps/api/src/verification.ts`, which
names the route's effect: `read`, `change`, `end-self`, `destroy`, `credential` or `disclose`, or `public` for a route that serves
visitors without a session.
`verificationLevel` in `@davloom/laws` turns the effect into a level: `none` for reads and
ordinary changes, `confirm` for ending one's own session, and `step-up` for destroying data,
changing a credential and disclosing records. A route without an entry answers 404, and
`app.test.ts` fails for it. Better Auth paths go in `AUTH_ACTIONS`, and the Dashboard's WebDAV
requests are classified by method in `davEffect`: a PUT is `destroy` unless it sends
`If-None-Match: *`, which only creates a file, and the Dashboard's upload sends it first.

The Dashboard needs nothing extra for a new step-up route: `apiCall`, `authFetch` and the WebDAV requests in
`apps/web/src/features/api/` catch 403 `verification_required`, open the shared "Verify it is
you" dialog, and send the request again once the person verified. A `confirm` action asks with
an `AlertDialog` before it sends, as `useSignOut` does.

## Supply chain and repository

- OSV-Scanner checks every package in `bun.lock` on each pull request and every week. Each exception in `osv-scanner.toml` gives its reason and an expiry date (`docs/ci.md`).
- Gitleaks scans each pull request's commits for secrets. CodeQL analyses the TypeScript, and actionlint and zizmor check the workflows.
- Dependencies are pinned to exact versions, and actions to full commit SHAs.
- No known Critical vulnerability is open: on the day of this check, the dependency scan reports none, and no exception covers one.
